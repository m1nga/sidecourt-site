# From a saved reference to an implementable change

Start with the current project, one user's task, real content and the authorized scope.
For each selected reference record an ID, source, `observed` or `unseen`, the actual
observation if inspected, and the transferable relationship. Do not invent a style analysis
from a title or README. Keep unverified reference ideas provisional.

For each task give a goal, one main method, related reference IDs, concrete steps and
observable acceptance checks. Include the original source and version in the project
record when versions matter. A list of twenty skills is not an implementation path.
Prefer the project's existing method over another framework with overlapping instructions.
Tool/skill availability, license, dependencies and paid prerequisites must be checked
before implementation. A copied prompt is not an installation or execution receipt.

`examples/capture-brief.json` is an original filled example. Run
`python3 <skill-dir>/scripts/brief.py --input PROJECT/brief.json --out NEW_FILE.html`.
The new file is private by default and self-contained. The renderer refuses unknown
reference IDs, invalid statuses, executable source URLs, missing steps/checks, and
existing output files. It does not evaluate visual quality or check whether the supplied
observations are true. Inspect and verify the implementation in the real product.
